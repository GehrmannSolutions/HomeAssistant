# Diorama development guide

This guide is for people working on the card's code. If you only want to use the card in your Home Assistant, you do not need it: install it from HACS as the [README](../README.md) explains, and build your home in the card's own editor.

It covers running the card from source against a local Home Assistant, the editor's commands, the catalog, how pieces show device state, and the card config format that the editor writes.

Custom Lovelace card for Home Assistant: an interactive 3D model of the flat with lights, blinds and sensors bound to entities. React + Three.js, built with Vite into a single `dist/card.js`.

## Development

Requires a Home Assistant instance running in Docker with a `compose.yaml`.

### Demo Home Assistant

The quickest way to see the card working is `ha-demo`, a Home Assistant in Docker with the demo flat on a dashboard, bound to the entities of Home Assistant's Demo integration. Build the card with `pnpm build`, run `docker compose up -d` in `ha-demo` and open http://localhost:8124. [ha-demo/README.md](../ha-demo/README.md) has the details.

### Day to day: dev server with live reload

Home Assistant caches files under `/local` aggressively, so during development the card is served from the Vite dev server instead.

```bash
pnpm install
pnpm dev
```

In Home Assistant go to Settings > Dashboards > three-dot menu (top right) > Resources and add:

- URL: `http://localhost:5173/src/dev/entry.ts`
- Type: JavaScript module

Every save rebuilds and reloads the dashboard. No cache busting needed. Keep only one of the two resources (dev server or `/local`) enabled at a time, otherwise the element gets registered twice.

The dashboard fetches that URL on every load, so the dev server has to be running whenever the card is on screen. When it is not, Home Assistant says **Custom element doesn't exist: diorama-card**: nothing answered, so the module never ran and never registered the element. A reload will not help while the server is down. Start `pnpm dev` again, or switch the resource to the `/local` build below.

### Diorama tiles

The tiles live in `src/tiles/` and are registered from `src/main.tsx`, so they ship in the same `card.js`. `host.tsx` is the base every tile's element extends: it loads the styles from `tiles.css` into the shadow root, checks the config and follows the room filter. `Tile.tsx` is the shell the entity tiles share, and `cards/` holds one view per card. `sidePanel.ts` is the `dio-side-panel` element the diorama card wraps itself in when `side_panel` is on, a plain element with no React that `WithSidePanel.tsx` mounts. It puts the diorama and each tile `auto.ts` makes from the plan in Home Assistant's own `hui-card`, so the room filter can hide them. It needs a real Home Assistant to try, since the dev page has no `hui-card`. The room filter itself is `src/lib/roomFilter.ts`, which the diorama card sets whenever it flies to a room.

`http://localhost:5173/src/dev/tiles.html` shows every tile against a mock Home Assistant whose states change when tapped, in a mock sections grid, with buttons to set the room filter. Add `?light=1` for a light dashboard. Service calls and more info requests are logged in the page. The user facing reference is `docs/TILES.md`.

`http://localhost:5173/src/dev/cards.html` shows every card the card picker suggests for a mock entity of each kind, one kind of card at a time from the menu at the top, each style at every size it comes in, and only one entity for each card that looks the same. Tapping, dragging and typing change the mock states the same way. Add `?light=1` for a light dashboard.

### Production build into Home Assistant

This is what the mini PC will use. It also works locally to test the real bundle.

```bash
pnpm build
```

Mount `dist/` into Home Assistant. In `compose.yaml`, add a volume under the Home Assistant service, next to the existing config volume:

```yaml
volumes:
  - ./config:/config
  - ${HOME}/Documents/Repos/ha-diorama/dist:/config/www/diorama
```

Then:

```bash
docker compose up -d
docker compose exec homeassistant ls /config/www/diorama
```

You should see `card.js`. If Home Assistant was started before `/config/www` existed, restart it once so it serves `/local/`.

Register `/local/diorama/card.js?v=1` as a JavaScript module resource. Bump `?v=` after each new build so browsers pick it up. `pnpm watch` rebuilds `dist/card.js` on change if you want to test the bundle continuously. The build writes into a staging folder inside `dist` and renames the file into place, so Home Assistant never serves a half written `card.js`: a browser that fetched one mid write throws on load and then reports that the custom element does not exist until the page is reloaded.

## Editor

The card's visual editor is a top-down drawing tool. Open it from the card's edit dialog.

Editing the card shows Home Assistant's own card dialog first, with its visibility and layout tabs, and the card's own tab, `src/editor/CardPanel.tsx`. It has the Open editor button first, then the side panel switches and, while the panel is on, an Edit widgets button that opens a page in place of the settings. That page shows the home's and each room's tiles under their names, which can be typed over and moved up or down with the arrows beside them, as the panel lays them out (`src/editor/WidgetGrid.tsx`, which moves them with `motion`'s drag and layout animations), to drag into order, resize from a corner, take out or hide, with the hidden ones as rows to bring back and an entity search under them to add entities that have no piece on the plan. The pen on a tile opens the widget picker on a page of its own, where a tap on a card makes it the only one and the plus in its corner adds it to the others, each change saved as it is made, and whose Back or Done returns to the widgets page, and its Back to the settings. An entity with several tiles has a list in `tiles` and is named once for each in the room's `order` or the home's `entities`, which `panelWidgets` in `src/tiles/auto.ts` turns into the panel's widgets. The controls of the 3D view come last. The editor opens fullscreen from there. Save saves the card to the dashboard and keeps editing. Save & Close does the same and leaves, with Home Assistant's dialog still open behind it, so closing that dialog afterwards keeps the edits. Its own Save, which Home Assistant greys out when there is nothing left to save, is switched back on, and pressing it closes the dialog. A card still being added is saved by that dialog's own Save the first time, since saving it from here could add it twice. Close returns to the dialog. With nothing changed since the last save it closes straight away; otherwise it asks first, with Save & Close to save the changes and leave, and Discard to go back to the last save, or to how the editor opened when nothing has been saved since. The back button, a phone's own too, does the same as Close, as the editor adds its own entry to the browser's history while it is open. `src/lib/backButton.ts` keeps Home Assistant's dialog from closing along with it, since Home Assistant closes its dialog whenever the browser comes back to that dialog's entry. The 3D view is open under the plan when the editor opens, and the cube toolbar button (P) closes and reopens it. It takes the bottom half of the column. Drag the divider between them to give either one more room. The 3D view frames the plan by itself until you orbit, pan or zoom it. From then on the camera stays where you put it, so editing does not throw your view away. Three named buttons sit in the view's top right corner. The rightmost, Save opening view, saves where the camera stands as the view the card opens with, and the view opens there in the editor too from then on. Until one is saved the card opens on the whole plan, framed. The Framed rooms section of the card's settings, above Background, picks rooms for the whole home's view to zoom in on, as if they were the only ones, written as `frame_rooms`. The rest still show where they fall in the picture and still take clicks. With none picked, every room is framed. A saved view keeps its angle on a card of any shape, but the camera is always framed again along that angle, centered, so the home fills as much of the card as it can, right to its edges on a wide card and running a little past its sides on one narrower than 600 px, as on a phone, backing off first where the whole home would not show in it. A card that grows or shrinks is framed again, unless the camera has been moved. Once one is saved the button reads Replace opening view. Fly to view beside it flies the camera to the opening view, saved or not, and Forget view at the far left, greyed out until a view is saved, forgets it and flies the camera back to the framed plan. The plan frames itself the same way, so changing the split keeps everything in view unless you have panned or zoomed it yourself.

- Draw room (D): click to place corners, click the first corner or press Enter to close.
- Select (V): click a room to select it, drag corners to move them, drag edges to resize, drag a room to move it. Right click a corner, edge, room or the canvas for a menu.
- Fit view (F), drag empty space to pan, wheel to zoom.
- Corners snap to a 20 cm grid and to other rooms' corners and wall lines. Hold Shift while drawing or dragging to snap to 1 cm instead, and pieces dragged with Shift held move by 1 cm rather than 5.
- Trace image: the image button in the toolbar lays a picture of a plan under the drawing to trace the rooms over. It starts as dark lines only at full opacity. Its panel sets the opacity, the width in meters and what shows: the whole picture, or only its dark or light lines in the color of the theme's text, with the paper left out. The picture is selected like anything else: a click on it where nothing is drawn over it, or one more click on a room already selected, puts a frame around it. Drag it to move it, drag a corner to size it around its middle, press Delete to remove it, and click elsewhere or press Escape to let go. Rooms and pieces always take a press before the picture does, and it is the last stop when clicking down through a pile. The picture is scaled down to 2400 px on its longest side and kept in this browser's local storage (`src/editor/trace.ts`), never in the card's config.
- Rooms never overlap. While dragging, the room follows the pointer and turns red where it would overlap. On release it lands on the nearest valid position, sliding along the free axis. A corner cannot be drawn inside a room or through one.

The sidebar shows the decoration catalog. Selecting a room fills it with a block for the room instead: its name, the Home Assistant area it stands for, the floor under it, its camera view, a button to delete it, and a cross that puts the block away and brings the catalog back. The cross lets go of the block, not of the room, so what is added next still lands in it. Selecting an item inside the room shows that item instead. An area can be linked to one room only. Radius and color can be set per room in the YAML.

Every room has a view. Until one is saved it is the room alone filling the picture, looked at from the same side and height as the view the card opens with, and it follows the room as its outline changes. To choose it yourself, orbit the 3D view to where the room looks best and press Use current view in the room's block. In the card, clicking a room's floor flies the camera to its view and the rest of the home fades away, so the room stands alone and only what is in it takes a press. Clicking outside it or clicking its floor again flies the camera back and fades the other rooms in again, however the camera has been turned, panned or zoomed in the room since. The back button does the same, a phone's own too: flying to a room adds an entry with the same address to the browser's history, which going back takes off, and going home any other way takes it off as well (`src/lib/backButton.ts`). A click on empty space anywhere in the dashboard's view does the same while a room is in view: the gaps between cards and sections, the view's background, or the side panel around its tiles. A click on a card, a badge or anything that can be pressed does not, nor one in a dialog or the header (`src/lib/emptyClick.ts`). The two fades run together, the old picture going as the new one comes, for as long as the camera's flight takes. A door, sliding door, garage door, window, blind, curtain or awning belongs to every room whose outline passes within 30 cm of it, not only the one it was put in, so it stays and takes presses in the view of either room (`src/decoration/between.ts`). Put it in the room whose side of the wall it should hang on. From the whole home, with rooms first, a click on such a piece with a device goes to the room it is looked at from, and one with no device, like a door, goes through it to the room beyond, as walking through it would: a door seen from the living room leads into the room behind it. The way the camera faces decides, not where it hangs, so turning the home round to see a door from its other side sends the click to the other room. Only a camera looking straight down, which faces neither way, falls back to the side of the wall it is over. With the camera on a room, a click on such a piece with no device, and no blind or curtain to work, goes through the wall: the camera flies to the room on the other side. Two rooms whose outlines share a stretch of at least 50 cm with no door, sliding door or garage door between them are taken as open to each other: with the camera on either one, a triangle as thick as a floor, rounded all over and made of the other room's floor, its color and its pattern, lies just past the middle of the longest stretch they share, or of the widest part of it clear of the windows, curtains and other pieces hung on that wall, so none of them stands in front of it, pointing into the other room, and a room a door leads into gets one too, just past the door, and a click on it flies there as a click on a door would. Under the pointer it lights up a little and leans further on its way. The triangles only show around the room they lead out of, never with the whole home, and the room's view backs off to keep them in the picture. Its solid is a flat core grown out the same distance every way, so the rounding of a side always runs exactly into the rounding of a corner (`src/geometry/passages.ts`, `src/geometry/pebble.ts`, `src/scene/Passages.tsx`). A selected room's block in the editor lists the rooms beside it under Rooms beside it: one a door leads into says which door, and each has a switch for its triangle. A switch turned off adds that room's id to the room's `hide_arrows` list, which leaves out only the triangle from this room into that one, not the one coming back. The fade is of the finished picture, not of the things: for as long as it lasts the frame is drawn twice, the whole home and the room alone over it, and the hidden rooms are moved to a layer the camera does not look at rather than taken out, so no light leaves the scene and no shader is built again (`src/scene/focus.ts`, `src/scene/Effects.tsx`). The eye beside the button flies the editor's camera to the room's view, and the cross, there once a view is saved, forgets it and goes back to the one the room comes with. Orbiting during a flight takes the camera over. Once the camera has left the view the card opened with, by orbiting or by flying to a room, a click on the empty space around the home flies it back there. On a touch screen a finger that sets off up or down over the card scrolls the dashboard, so the card never traps a scroll. One that sets off sideways turns the home, and tilts it too for as long as it stays down. Two fingers pan and zoom as before.

The Rooms first switch, under In the card in the card's settings, chooses what a click on a device goes to first in the card. Devices first, the default, acts on a device from wherever it is clicked. Rooms first sends the first click to the room the device stands in, and the device answers once the camera has flown there. A long press or a right click opens the device's dialog either way.

### Editing commands

The commands every drawing program has, with the same keys. They all show in the right click menu of whatever they act on, with their shortcut.

| Command                    | How                                                                                                             |
| -------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Duplicate                  | Alt or Option and drag, or Ctrl D, Cmd D on a Mac                                                               |
| Copy and paste an item     | Ctrl C and Ctrl V. Paste drops the copy in the selected room, so an item can be copied from one room to another |
| Rotate 90°                 | R                                                                                                               |
| Move by one grid step      | Arrow keys, with Shift for a 5 cm step                                                                          |
| Delete                     | Del or Backspace                                                                                                |
| Deselect, cancel a drawing | Escape                                                                                                          |

Alt and drag copies furniture and rooms. A duplicated room keeps its shape and floor but not its area, since an area stands for one room. A copy released on top of another room moves to the nearest free spot. A copy is never bound to the original's entity, since an entity is stood in for once.

The toolbar's sun button opens a time of day slider for the 3D preview, N,
starting at one in the afternoon: what is being drawn should look the same
whatever the hour outside, and the slider walks the room through noon, the
golden hour, dusk and the middle of the night. It moves the preview only,
never the card. The sun's direction, which decides which way every shadow
falls, is set in the card's settings under In the card, in steps of 5°, and
the preview there follows it as it is dragged.

The sidebar shows the catalog of furniture and fixtures. Floor patterns are drawn at their real size, boards 16 cm wide and 1.6 m long, tiles 40 cm across, carpet in a pile of about 8 cm, so the pattern size only has to change when a room should read coarser or finer. Pattern depth is how much the pattern shows at all: 0 leaves a plain tint, 1 is the surface as designed, 2 doubles its contrast and relief. The floor is painted from above, so the rounded edge and the sides of the slab carry the same boards as the top. The angle turns the pattern on the floor, for example to run the boards across the room instead of along it. An item is added to the selected room, or to the room the selected piece stands in, or to the last room either of them was in, so a run of items added one after another all land in the same room even as the selection moves to each new piece. With nothing ever picked it goes to a random room, from where it can be dragged. Hovering an item shows a small 3D preview, and clicking anywhere on its row places it in the room. Coming back to the list from the item finds it scrolled where it was. Selecting a placed item fills the sidebar with a larger 3D preview and its settings: the style it is drawn in when the kind comes in more than one, sizes, rotation with buttons for the four square turns on anything not hung on a wall, one color per part, and the device it stands in for. The preview, the item's name and the way back to the list stay at the top while the settings scroll. It is square until the handle under it is dragged to make it taller or shorter. It turns on its own until it is dragged, scrolled or panned by hand, and the button that then shows in its corner brings the view back. Searching a family name, kitchen or lights, lists everything in it.

- Rooms and items are picked at any time, with no mode to switch, and one at a time: picking a piece lets go of the room, and picking a room lets go of the piece. While a piece is dragged the room it would land in lifts a little, which is a hint, not a selection. Whatever is selected is drawn last, so it takes the press when two items sit over each other and its rotation handle is never covered. Clicking that spot again steps down to the item underneath, then to the room they all stand in, and round again, since something buried cannot be reached any other way. Dragging still moves whatever is selected. A selected room's corners and edges sit above the furniture, so a corner a sofa stands over can still be grabbed and moved. A press in the 3D view does what it would in the card, and in the editor also picks what it landed on, so orbiting around to a lamp and clicking it opens that lamp in the sidebar. A click on empty space around the model lets go of whatever was picked, the way one on the plan's background does. Orbiting the camera from there does not. Whatever is picked, a piece or a room, glows with a blue outline in the 3D view that follows its own silhouette, and carries on fainter where something stands in front of it. The outline is drawn only while something is picked, and never in the card itself.
- Items drag on the canvas, into any room. Wall items sit on the nearest wall and face into the room. Ceiling items show a dashed outline. Every footprint is drawn at its true size at any zoom, and only the icon on it keeps a fixed size so it stays legible.
- Tables, desks, counters, islands, sideboards, dressers, side tables, bookshelves, wall shelves, stools, benches, poufs, half walls, washing machines and dryers have a top other things can stand on. Drag a lamp, a kettle, a vase, a monitor or a TV over one and it lands on it: the top lights up while the item is over it. A wall shelf's top is the strip of room in front of the wall it hangs on, so a plant dragged up to the wall under a shelf lands on its board. Moving the support takes everything on it along, and deleting the support leaves them on the floor. The sidebar's Standing on row steps such an item, with an arrow down and an arrow up, through every height there is where it stands: the floor, each top under it, and the height it has on its own where there is nothing to stand on. A height saved with the slider this replaced is kept as one of the steps. A piece stepped down to the floor stays on it when it is dragged, which is how a speaker goes under a table. A hob and a sink let into a worktop instead of resting on it. An item that stands on nothing sits at the height it has on its own, counter height for a kettle, until it is stepped down to the floor. A wall item hangs at its height, except a door, a garage door and a radiator, which stand on the floor, and a window, which starts at its sill.
- An item can stand in for a Home Assistant entity, which is the only way an entity reaches the plan: nothing is placed on its own. The item panel has a Device dropdown listing every entity that drives at least one of the things that item can show, the ones that fit best first, each with the controls it brings at the end of its row and the pieces it already drives listed under its name. A list of more than a handful searches itself: a box at the top of the panel takes the focus as it opens and filters on the entity's name and its id, the arrows walk what is left and Enter takes it. An entity can have several items, an item stands in for one entity, so an entity already behind another piece is still on offer. When it is behind more than one, the panel lists the others under Also driving: a row goes to that piece, the bin beside it asks first and then lets go of it. The room and position of the binding follow the item, and an item on the plan with an entity behind it carries an amber outline. Bound items take the entity's clicks and show its state, for example a lamp glows with the light's brightness and color. Clicking an item acts on its entity, and one with nothing to switch, like a camera or a thermostat, opens its dialog. Right clicking it, or holding it on a touch screen, opens Home Assistant's own dialog for the entity, where everything a click cannot do lives: brightness, color, a cover's exact position. A press that wanders is the camera being moved, so it never opens the dialog. Deleting an item, or the room it is in, drops the binding with it. Entities on offer: lights, switches, groups, which a click switches as one through Home Assistant's own toggle, covers, media players, fans, climate, humidifiers, locks, cameras, vacuums, temperature and humidity sensors, door, window and motion sensors, and buttons, which a piece that takes a press plays once when they are pressed. Diagnostic and configuration entities are left out.
- An item with more than one look and no entity behind it can be tried in each of them, in the editor only. Its panel has a Try its states section with a switch for on and off, a slider for each level (brightness, speed, how far a cover is open, a blind's slats, a window's tilt) and, for lights, a default, white or color tint. The switch is fully on or fully off and the first slider anything in between, each moving the other: switching off takes the slider to 0%, and any level above 0% is on. Clicking the item in 3D switches it too, the way it would act on an entity. A click on a speaker or a TV that is playing pauses it and one on a paused one plays it again, so a click never switches off what it has on. One with nothing on, or one that cannot play or pause, is switched on and off, the same as its tile. Nothing tried is saved, and Reset puts the item back. An item with an entity shows the entity's state instead.

Things are small seen from across a room, so a press that lands on nothing is tried again in rings around itself, growing outward to `PICK_RADIUS_PX` in `src/theme.ts`. The first thing it finds takes the press, which means a lamp does not have to be hit exactly. The floor is checked part way through the rings, where `PICK_ROOM_AT` in the same file says: 0 checks it before the first ring, 1 only once every point has been tried, and 0.5 half way. Up to that point a press near a lamp goes to the lamp rather than to the room under it, and a press that finds nothing at all is a press on the room, if the floor was under it.

Everything that moves is eased rather than switched. Home Assistant reports a cover's position every second or so while it travels, and a switch flips in one step, so without this a sliding door would stutter along in jumps and a window would snap open. Doors and casements swing, panels travel, curtains draw, screens roll, fans come up to speed and lamps fade up and down. A travelling cover only ever heads for the position Home Assistant last reported, never past it: what the reports give is the pace, since how far it moved between one and the next divided by how long that took is how fast the cover travels. Driving at that pace means arriving just as the next report lands, so a set of steps reads as one movement.

- A window is divided into casements by how wide it is, each leaf between half a meter and a meter. Left alone they open from the middle, the way a pair of French casements does. Hinge right swings every one of them from its right edge instead. A sliding door takes its number of panels as a setting, and the panels split the width between them and gather one in front of another as it opens.
- A kind can come in more than one style, and it is still listed once in the catalog: the item's own panel has a Style dropdown above its sizes. A pendant is a slatted drum or a glass globe in a wooden cage, and the color slots follow the style, since the two are made of different parts. Every search box has a cross to empty it.
- Items are grouped by family in the sidebar, with a search box. Every model is built from primitives in code, in a Scandinavian vocabulary: pale oak, chalky whites, muted greens and clays, rounded frames on tapered legs, plump linen upholstery.

### My models

The catalog starts with My models, the 3D models imported into this card (`src/decoration/models.ts`, `src/editor/importModel.ts`). Import a model takes a .glb, or a .gltf picked along with the .bin and other files it names, reads it in the browser and places one of it the way a click on a catalog row does. From then on it is listed under My models with the file's name and is placed, dragged, turned, copied and deleted like any other piece, and the bin on its row takes it out of the catalog with every piece of it on the plan, after asking.

- Only the shape is kept (`src/scene/decor/modelShape.ts`). The file's materials, textures, normals and everything else are thrown away and the model is painted in the card's own plain paint, shaded round across edges softer than 40 degrees and sharp across harder ones. Each part is a color in the item panel, all starting in the same linen. A part is a mesh, named by its node or its mesh, with Blender's .001 copies and underscores taken out, so the four legs of a table named Leg, Leg.001 and so on are one part. A mesh in several materials is one part per material. A part with no name is Part 1, Part 2 and so on. A model with more than 16 parts is gathered by material, and past that the smallest go together as Other, since every part is a draw call.
- Width, depth and height stretch the model along each axis to fit that box, and start at the model's own size. glTF is in meters, and a model that would come out more than 30 m across is taken for centimeters, or millimeters, and scaled down.
- It stands on the floor to start with, and can stand on a table like a lamp. The item panel's Model block renames it and mounts it on a wall, with its back to the wall and an Off floor slider for how high its bottom edge hangs, or from the ceiling by its top. The name and the mount are the model's, so they change every piece of it. A piece moved onto a wall snaps to the nearest one, and one moved off it stands just in front of where it hung.
- It stands for no device: binding an entity, and opening its dialog on a click, are left for later.
- A model of more than 60,000 triangles is refused, with a word on simplifying it, for example with Blender's Decimate modifier, and one of more than 20,000 is taken with a warning in its panel that a wall tablet may stutter on it. A file compressed with Draco is refused too, since three's Draco decoder would add almost 2 MB to `card.js`. Meshopt compressed files are read.

The shape is kept in the card config under `models`, so the card shows it on every screen without anything else to set up. Home Assistant saves a dashboard in one websocket message, which it takes up to 4 MB of (aiohttp's default, a bigger one closes the connection with 1009), so a model is refused past 1 MB in the config and all of a card's models past 2.5 MB together, leaving room for the rest of the dashboard. Each corner is three 16 bit numbers across the model's box and each triangle three 16 bit indexes, or 32 bit past 65,536 corners, both in base64: a model of 20,000 triangles takes about 250 kB. Home Assistant's media upload was tried and does not work for this: it only takes files sent as images, audio or video, and serves what it holds by the type its extension says, so a .glb sent as an image is stored but never served back. The link button beside Import a model takes the address of a .glb or .gltf Home Assistant serves instead, like `/local/models/chair.glb` for `/config/www/models/chair.glb`, read once to name its parts and then fetched by every screen that draws the card, which keeps the config small for a large model.

### Light in the room

The room takes its light from the time of day at the home. The card reads
`sun.sun`, so the hour before sunset arrives as a fade rather than a switch,
falling back to the entity's state and then to the clock on the device
showing the card when the sun integration is not there.

- By day the room sits in soft warm light: a sky above, a floor bounce below
  and a gentle sun on top of them. Shadows are filtered soft and the sun's
  map is kept coarse on purpose, so a piece gets a soft pool under it rather
  than a hard outline of itself.
- The light takes its color from how high the sun is standing: golden along
  the horizon at sunrise and sunset, near white overhead at midday.
- By night that wash drops to a dim warm glow and the lamps carry the room.
- The change takes about an hour each way. The sun climbs roughly ten degrees
  in the hour after it rises and drops the same in the hour before it sets, so
  the room starts dimming about an hour before sundown, is at night by
  sundown, and takes the hour after sunrise to come back up.
- `sun_direction` says where the sun comes from, in degrees clockwise from
  the top of the plan, which decides which way every shadow falls.
- Every lamp lights what is around it and throws the things beside it onto
  the floor. A lamp shade is not a wall: its frame and slats cast shadows
  while the parchment or opal in it passes light through and glows.
- Each kind of lamp has its own output, in `theme.ts`: a pendant hangs close
  over a table and sends its light down through a diffuser, so it gives about
  half what a floor lamp standing in the open does.
- Point light shadows are expensive, so the brightest few lamps cast them and
  the rest light the room without. A lamp casts from the frame it lights up,
  and the sweep only takes shadows away from the lamps past that budget. LED
  strips light along their length, which is a kind of source that cannot cast
  a shadow.
- The sun stands over the middle of the flat and its shadow covers exactly
  it, so the shadow map stays fine grained and a tabletop does not speckle.

### How items show device state

A bound device drives what the item does in 3D, when its signals match:

- Lamps and LED strips glow with the light's brightness, color and color temperature, taking on the color themselves rather than only tinting the room. A strip lights along its whole length.
- TVs and monitors play a picture on their screen, and are black glass when off. One bound to a media player that is on shows what plays the way its card does: the cover art, or else the colors of its app drifting, with the app's logo in the top left corner and the title in the bottom left one, and its light takes the main color of the cover or the app's own. A projector bound to a player throws the same picture. A cover drifts slowly in and out. A TV is set by its diagonal in inches, always in 16:9, and a motorized projector screen rolls out of its case at the ceiling by the cover's position. A lowered screen that a projector that is on faces shows the picture on the side the light comes from. Speakers and soundbars light a small indicator and send out sound waves in flat rings from just under their top, so they never cut into what they stand on, a soundbar from just above each end. Projectors throw a flickering beam, which reaches the corners of the picture when it lands on a projection screen, an ultra short throw one a wide, shallow beam up the wall above it, consoles light their bar, a PC tower lights up inside and a laptop lights its screen. A wall tablet that is on shows a dashboard of tiles, some lit amber, blue or green, or what a player bound to it plays. A wireless charger fades the phone, watch, earbuds or tablet in on top of it while it charges, with a soft glow underneath, and fades it out again after.
- Blinds, shutters, curtains, garage doors and awnings move to the cover's position, and a blind's slats turn with its tilt. Doors and window casements swing open, a terrace pair opening both its leaves, a box sash slides its lower half up, a sliding window runs one pane over the other, and every window tilts its opening pane in at the top, a tilt that drops to nothing as soon as it opens. A sectional garage door rolls up its track and its panels slide into one another under the ceiling rather than stacking, and sliding doors run along their track, partway when the cover reports a position. A driveway gate swings its two leaves open or runs along its fence by the same position. A device that only switches drives the same items fully open and shut. A blind's Other side of wall switch hangs it on the far side of its wall, outside the room it is in, with or without a room there: the piece is turned round where it meets the wall and keeps its room. A window, door, sliding door or garage door with no device of its own hands its clicks to the blind or curtain with a device that hangs over it, within the opening's width of its middle, so a click on the glass works the blind. With more than one over it, the click goes to the cover over the stretch of the opening it landed on, a blind before a curtain where both hang there. A door, sliding door or garage door that leads into another room still takes the camera there on a click, and only its long press goes to the cover.
- In the card, a blind, a shutter, a projector screen, a garage door, an awning, a sliding door or a sliding driveway gate bound to a cover that takes a position can be dragged along the way it runs, so a press on a blind that goes up or down moves it with the finger, a small label says the percentage, and letting go sends the cover there with `cover.set_cover_position` (`src/scene/decor/drag.tsx`). A press that runs across it instead, or that is held still for the long press first, turns the camera as before, and so does a cover too small on screen to drag. The piece always shows where the cover really is. A see-through light blue copy of it, just wider and just in front so it shows over the piece whichever way it goes, follows the finger with no easing, and stays where it was let go while the cover travels there, until it gets there or has stood still for three seconds. It fades in and out. A drag that starts while it waits starts from it. A drop within 2% of either end goes all the way. A press that lands just beside the cover, or between the slats of a blind, starts the drag as if it had landed on it, found by the same search around the press that a click uses (`src/scene/pick.tsx`). A press on a window or a door with no device of its own, under a cover that can be dragged, drags that cover, as a click on it works it, except on a door that leads into another room. With Rooms first on, a cover is only dragged where a click on it would work it, so not in a room the camera has not flown to yet, and the press turns the camera instead. Pieces are never dragged in the editor.
- A device with more than one percentage, a cover with a position and a tilt, says which one feeds each percentage of the item it stands behind. A window and a blind take two: how far open they are, and how far tilted.
- Fans spin, faster at a higher level, and washing machines turn their drum. Air purifiers and humidifiers breathe out a plume. Air conditioners, and duct grilles with them, blow out a haze of fine specks of air in the color their tiles show: orange while heating, blue while cooling, yellow while drying, teal while only moving the air, and plain while waiting. A thermostat's face and its halo glow in the same color.
- A robot vacuum comes with the dock it charges on. The dock stays where the piece was placed, since that is the thing plugged into the wall, and the robot leaves it while the vacuum is cleaning: it sweeps the room in long parallel passes, each one cut back to the stretches clear of the furniture standing on the floor, and the move from the end of one pass to the start of the next is routed across the free floor as well, so no leg of the round crosses a sofa. A rug is the one thing on the floor it drives straight over, along with everything that hangs on a wall or from the ceiling. When the vacuum stops it drives straight back to the dock by the shortest way across that same free floor, rather than retracing everything it has just swept, and parks facing out of the dock. A vacuum has no toggle service, so a press sends it out with `vacuum.start` and home with `vacuum.return_to_base`, by what it is doing at the time. A press on either the robot or the dock does what a press on the piece does.
- Radiators and towel rails warm up, hobs light their rings, ovens glow behind the glass.
- Fridges and dishwashers open their doors, upper cabinets open theirs, counters and islands slide out their drawers and swing open their doors, a toilet lifts its lid, and kettles and coffee machines steam. A sink in a counter or a basin holds a little water when its tap is on. Toasters push down their bread and glow in the slots, and cooking robots and air fryers light up and steam.
- Taps run water into kitchen sinks and basins, a bath fills to a bathing level while its tap runs, and a shower rains from its head.
- Desks rise to standing height, taking everything on them along.
- Fireplaces and stoves burn inside their firebox behind clear glass, a Christmas tree runs warm white fairy lights through patterns of steady, blinking, rolling and alternating, a pet feeder drops kibble into its bowl, a fountain spouts water up from its dome, and a water heater lights its flame or display.
- Hot tubs light up, bubble and steam, pools light their water and ripple out in round rings from several spots, sprinklers throw a sweeping arc or slow drops from each drip emitter, a louvred pergola opens by the cover's position, the slat roof sliding its slats to the back and the cedar one turning its blades, and a sauna lights its stove and lets off vapor.
- A 3D printer lights its chamber and its screen while it prints, and its toolhead runs to and fro. It prints while its switch is on, while a sensor says in words that it is printing, running, preparing or heating, or while a progress sensor is between 0 and 100, and with a progress the print on its bed is as tall as it has got, the bed going down under it, so a finished print stays on the bed. A router lights its row of status lights, and a mesh puck the ring on its top.
- Thermostats, alarm panels and air quality sensors light their display. A smart lock turns its knob upright when locked, a motion sensor's white dome turns teal when it sees someone, a smoke detector blinks red and throws that red on the floor and furniture around it when it raises the alarm, from a smoke binary sensor, a carbon monoxide sensor at 50 ppm or more, or a sensor whose state is a word such as detected, alarm or emergency, a leak sensor glows blue and a puddle spreads round it when it gets wet, and a camera lights its LED.
- A button, a script or a scene behind a piece plays what the piece does once and then goes back to how it was. Every piece that switches takes one, except sensors, locks and readouts such as a thermostat, which have nothing to play. Most switch on for 2.5 seconds, a light blinks for under a second at full brightness, anything that opens, a cover, a fridge, a cabinet or a lid, stands fully open for only about half a second before it shuts again, and a fan keeps its own speed for one turn round. A litter box rocks one turn over and back to scoop, a pet feeder drops one portion, a doorbell lights the ring round its button, a door buzzes open and a coffee machine makes one cup in 10 seconds. The times are in `src/scene/decor/pressed.ts`. A press counts as soon as it is clicked, and the time Home Assistant then reports for it is folded into that same run. In the editor, Try its states has a Press button for these pieces, named for what it does where that is clear.

- Plants take Home Assistant's own plant entities and the sensors that watch them, soil moisture, soil temperature or the humidity round them, offered first. A plant wilts when its soil runs dry: from its Dry below setting, 20% to start with, its leaves fade toward straw, its soil pales and its foliage sinks toward the pot and spreads, all the way at 15 points under it, and it perks up again over a few seconds once watered. It reads the moisture from a moisture sensor, a moisture binary sensor, which is dry when off, or a plant entity's moisture, or its moisture low problem when it has no reading. A temperature or humidity sensor leaves it as it is. A click on it opens the entity's dialog.

Only entities that drive at least one of the things an item can show are on offer for it, so an item is never bound to something it cannot express.

### When changes don't show up

Home Assistant and the browser cache resources aggressively. After a rebuild, hard refresh the page. If that isn't enough, bump the version in the resource URL (`?v=2`).
